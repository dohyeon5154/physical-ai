
농작물 질병 감지기 PRD (Product Requirements Document)

문서 버전: v1.0 | 작성일: 2026-10-06 | 작성자: Physical AI PM

제품 개요: 시설 원예 온실에서 레일 주행형 카메라가 작물 잎을 촬영하고, Edge AI가 잎 색상 변화를 분석해 질병을 판별합니다. 판별 신뢰도와 위험도에 따라 해당 구역 방제 장치를 자동으로 작동시키거나, 관리자에게 승인 요청 알림을 보냅니다.

기본 가정

대상 작물: 시설 토마토 (가정)
대상 시설: 1ha(약 3,000평) 연동형 비닐온실, 방제 구역 8개 (가정)
기존 인프라: 온실에 파이프레일(난방관 레일)과 구역별 방제 배관, 복합환경제어기가 이미 설치되어 있음 (가정)
1. 문제 정의 (Problem Statement)
1.1 현재 문제
시설 토마토의 주요 병해(잎곰팡이병, 흰가루병, 잿빛곰팡이병, 겹둥근무늬병, 역병, 황화잎말림바이러스)는 초기 증상이 잎의 국소적인 색 변화로 나타납니다. 예를 들어 잎 앞면이 옅은 황색으로 변하거나 흰 반점, 갈색 동심원 반점이 생깁니다.
발견이 3~5일만 늦어도 고온다습한 온실 안에서 인접 구역으로 빠르게 번집니다. 이 때문에 연간 수확량 손실률이 8~12%에 이릅니다 (가정).
확산을 막기 위해 온실 전체에 예방 방제를 하는 관행이 있어, 농약 사용량과 비용이 과다하고 PLS(농약허용물질목록관리제도) 위반 위험도 커집니다.
1.2 기존 방식의 한계
기존 방식	한계
작업자 육안 예찰	1ha 기준 하루 2~3시간이 소요됩니다. 숙련도에 따라 판별 편차가 크고, 잎 뒷면이나 하위엽은 놓치기 쉽습니다.
정기 예방 방제(달력 방제)	발병 여부와 관계없이 전 구역에 살포하므로 약제비와 노동력이 낭비되고 저항성 병원균이 생길 수 있습니다.
환경 센서 기반 발병 예측	온습도 조건으로 "발병 가능성"만 알려줄 뿐, 실제 발병 위치와 병명을 특정하지 못합니다.
스마트폰 사진 진단 앱	사람이 직접 찍어야 하므로 상시 감시가 불가능하고, 방제 장치와 연동되지 않습니다.
1.3 핵심 가치
조기 발견: 육안 예찰보다 평균 3일 이상 빨리 발병을 감지합니다.
국소 정밀 방제: 발병 구역에만 방제하여 농약 사용량을 30% 줄입니다.
예찰 노동 자동화: 일일 순회 예찰 시간을 70% 줄입니다.
이력 데이터 축적: 구역별 발병 이력과 방제 이력을 기록해 PLS 준수와 GAP 인증 대응을 지원합니다.
1.4 AI가 필요한 이유
잎 색 변화는 질병만으로 생기지 않습니다. 영양 결핍(질소·마그네슘 결핍에 의한 황화), 수분 스트레스, 노화엽, 조명 반사도 비슷한 색 변화를 만듭니다. 단순한 색상 임계값(Rule-based HSV 필터)으로는 오탐률이 30%를 넘습니다 (가정).
반점의 형태, 분포 패턴, 색상 그라데이션, 잎 위치(상위엽/하위엽)를 함께 학습한 딥러닝 모델이 있어야 질병과 비질병 색 변화를 구분할 수 있습니다.
여기에 온습도와 엽면습윤 시간 같은 환경 데이터를 결합하면, 같은 색 변화라도 발병 위험도를 다르게 평가할 수 있습니다. 이 다중 입력 융합 판단이 AI의 핵심 역할입니다.
2. 사용자 시나리오 (User Scenario)

페르소나: 김OO (45세), 1ha 토마토 온실 운영자. 작업자 3명을 고용하고 있으며 스마트폰 사용에 익숙합니다.

Step 1. 제품 설치
설치 엔지니어가 기존 파이프레일에 스캐닝 카트 2대를 올리고, 카트에 RGB 카메라 4대(좌·우, 상·하단), LED 상시 조명, Edge AI 보드를 장착합니다.
구역별 방제 배관에 전자밸브를 달고 PLC에 연결하며, 엽면습윤센서와 온습도센서를 구역마다 1세트씩 설치합니다.
관리자는 웹 대시보드에서 온실 평면도에 구역(Zone 1~8)을 등록합니다. 그리고 작물 생육 단계와 구역별로 등록된 방제 약제, 수확 전 안전사용기간(PHI)을 입력합니다.
카메라마다 컬러 체커(24색 기준표)로 색 보정 캘리브레이션을 진행합니다.
Step 2. AI 데이터 수집
스캐닝 카트가 하루 2회(06:00, 15:00) 레일을 따라 이동하며 작물 열마다 잎을 촬영합니다. 1회 순회에 약 90분이 걸리고, 1ha 기준 약 12,000장을 촬영합니다.
촬영할 때마다 카트 위치(레일 번호, 거리 엔코더 값)가 함께 기록되어, 이미지마다 구역과 위치 좌표가 붙습니다.
구역별 센서는 온도, 습도, 엽면습윤 시간, 일사량을 1분 간격으로 수집해 게이트웨이로 보냅니다.
Step 3. AI 분석 수행
1차 (Edge): Jetson 보드가 촬영 즉시 잎 영역을 검출합니다(Object Detection). 검출된 잎마다 색 보정(Lab 색공간 정규화)을 거친 뒤 질병 분류 모델로 9개 클래스를 판별합니다. 클래스는 정상, 병해 6종, 영양결핍, 생리장해입니다.
2차 (Edge): 같은 구역에서 같은 병으로 판별된 잎이 여러 장 나오면 집계해서 구역 발병 점수를 계산합니다. 잎 한 장의 오탐으로 방제가 작동하는 일을 막기 위한 단계입니다.
3차 (Server): 최근 72시간 환경 데이터로 계산한 발병 위험도를 구역 발병 점수와 결합해 최종 위험 등급을 산출합니다.
Step 4. 판단 결과 생성
등급	조건	판단
🔴 긴급	신뢰도 0.90 이상, 같은 구역 병반 잎 5장 이상, 환경 위험도 '높음'	자동 방제 후보
🟠 경고	신뢰도 0.70~0.90, 또는 병반 잎 2~4장	관리자 승인 요청
🟡 주의	신뢰도 0.50~0.70, 또는 영양결핍·생리장해 판별	정보성 알림, 다음 순회 때 재촬영
🟢 정상	위 조건에 해당 없음	로그만 저장

결과에는 구역, 병명, 신뢰도, 병반 잎 수, 대표 이미지 3장, 권장 약제가 포함됩니다.

Step 5. 장치 제어 및 알림
긴급 등급: 시스템이 안전 인터락을 먼저 확인합니다. 확인 항목은 해당 구역에 작업자가 없는지(출입 RFID와 PIR 센서), 수확 전 안전사용기간 안인지, 당일 같은 약제를 이미 살포했는지입니다. 모두 통과하면 PLC로 해당 구역 전자밸브를 열어 등록된 약제를 정량 살포합니다. 동시에 환경제어기에 환기와 제습 강화를 지시합니다. 인터락 중 하나라도 걸리면 자동 방제를 막고 경고 등급으로 내려 관리자 승인을 요청합니다.
경고 등급: 카카오 알림톡으로 대표 이미지와 "방제 승인 / 보류 / 오진 신고" 버튼을 보냅니다. 관리자가 승인하면 원격으로 방제가 작동합니다.
방제가 작동하는 동안 해당 구역 입구 경광등이 켜집니다.
Step 6. 결과 확인 및 후속 조치
관리자는 대시보드 히트맵에서 구역별 발병 현황, 방제 이력, 약제 사용량을 확인합니다.
오진이라고 판단하면 "오진 신고" 버튼으로 정답 라벨을 입력합니다. 이 데이터는 재학습용 데이터셋에 자동으로 쌓입니다.
방제 후 48시간 동안 다음 순회 촬영으로 병반이 늘었는지 추적하고, 방제 효과 리포트를 만듭니다.
매월 자동 생성되는 방제 일지(PDF)를 GAP 인증 기록과 농약 사용 기록으로 활용합니다.

4. 기술 스택 (Technology Stack)
구성	사용 기술	선정 이유
카메라	산업용 글로벌셔터 RGB 카메라 (Sony IMX296 기반, 1.6MP, Arducam/Basler 계열), 카트 1대당 4대	카트가 움직이며 촬영해도 모션 블러가 적습니다. 잎 색상 판별은 해상도보다 색 재현성이 중요합니다.
조명 / 색 보정	고연색(CRI 95 이상) LED 링라이트, X-Rite 24색 컬러 체커	시간대와 날씨에 따른 자연광 변화를 제거해 색상 일관성을 확보합니다.
이동체	파이프레일 주행 카트 (DC 모터와 로터리 엔코더)	기존 온실 난방관 레일을 그대로 쓰므로 설치비가 적게 들고, 엔코더로 촬영 위치를 정확히 남깁니다.
환경 센서	SHT45 온습도, 엽면습윤센서(METER PHYTOS 31), 일사량 센서, PIR 인체감지	엽면습윤 시간은 곰팡이성 병해 발병의 핵심 변수이고, PIR은 방제 안전 인터락에 씁니다.
MCU	ESP32-S3 (센서 노드), STM32F4 (카트 모터 제어)	ESP32는 Wi-Fi와 MQTT를 내장해 센서 노드 단가가 낮습니다. STM32는 실시간 모터 제어에 안정적입니다.
방제 제어	LS ELECTRIC XGB PLC, 구역별 24V 전자밸브, Modbus TCP	국내 온실 환경제어기와 호환성이 높고, 산업 현장에서 검증된 PLC 기반 제어로 안전성을 확보합니다.
Edge AI	NVIDIA Jetson Orin Nano 8GB, TensorRT (FP16/INT8)	40 TOPS로 카메라 4채널 실시간 추론이 가능합니다. 네트워크가 끊겨도 판별과 로컬 저장을 계속할 수 있습니다.
AI 모델 (검출)	YOLOv8s (잎 검출)	산업 현장에서 많이 쓰이고, TensorRT로 변환하기 쉽고 경량입니다.
AI 모델 (분류)	EfficientNet-B3 (9개 클래스 분류), Lab 색공간 정규화 전처리	정확도와 연산량의 균형이 좋고, PlantVillage 사전학습 가중치로 전이학습을 하기 쉽습니다.
AI 모델 (위험도)	LightGBM (환경 데이터 기반 발병 위험도)	정형 시계열 특징에 강하고, 판단 근거(Feature Importance)를 설명할 수 있습니다.
MLOps	Label Studio (라벨링), MLflow (모델 버전 관리)	오진 신고 데이터를 다시 라벨링하고, 모델 버전을 추적하고 롤백할 수 있습니다.
서버	Python FastAPI, Docker, NAVER Cloud Platform	국내 데이터 보관이 필요한 경우에 대응하고, 국내 농업 지자체 사업에서 많이 쓰입니다.
통신	MQTT (Mosquitto), 온실 내 Wi-Fi 6 AP, LTE 라우터(백업)	저대역폭과 불안정한 환경에 적합한 경량 프로토콜이고, LTE를 백업 회선으로 둡니다.
데이터베이스	PostgreSQL + TimescaleDB (센서·이벤트), MinIO/Object Storage (이미지)	시계열 센서 데이터와 이벤트 로그를 하나의 DB로 관리하고, 이미지는 저비용 객체 스토리지에 둡니다.
대시보드	React 기반 관리자 웹, Grafana (센서 모니터링)	온실 평면도 히트맵과 방제 승인 UI는 React로 직접 만들고, 센서 그래프는 Grafana로 빠르게 구축합니다.
알림 시스템	카카오 알림톡 (버튼형), SMS (Fallback), 현장 경광등	국내 농업인 도달률이 가장 높은 채널이고, 승인 버튼으로 원격 방제가 가능합니다.

5. 개발 범위 / 비범위 (Scope)
5.1 개발 범위 (In Scope)
레일 주행 스캐닝 및 자동 촬영: 스케줄 기반 순회 촬영, 엔코더 기반 위치 태깅, 카메라 4채널 동기 촬영
실시간 잎 검출 및 질병 분류: Edge에서 9개 클래스 판별, 색 보정 전처리 포함
구역 단위 발병 집계 및 위험 등급 판정: 잎 단위 결과 집계, 환경 위험도 결합, 4단계 등급 산출

6.6 최종 판정

판정: 조건부 투자 적합 (Conditional GO)

기준 시나리오의 투자 회수기간 약 40개월은 장비 내용연수(60개월)보다 짧고, 5년 누적 약 3,500만 원의 순이익이 예상됩니다.
다만 ROI의 약 40%가 "병해 손실 감소" 효과에서 나오므로, 실제 효과가 이 가정에 크게 좌우됩니다. 그래서 1개 동(약 0.3ha)에서 3개월 PoC를 진행하고, 병해별 재현율 0.90과 자동 방제 오작동률 2% 이하를 확인한 뒤 전체 시설로 확대하는 단계적 도입을 권고합니다.
비용 효율이 가장 큰 요인은 AI 모델 개발비(CAPEX의 36%)를 여러 동에 나눠 쓰는 것입니다. 3ha 이상 시설이나 지자체 스마트팜 보급 사업(국비 보조 50% 수준 가정)과 결합하면 회수기간을 24개월 이하로 줄일 수 있습니다.
